# PawCare Outcomes

- [x] **Full-stack project structure and documentation** — Use separate `/client` and `/server` folders. The server has clear `routes`, `controllers`, `models`, and `middleware` structure. Provide a README with setup steps, `.env.example`, an API endpoint list, and a simple flow diagram: User -> React frontend -> Express API -> MongoDB -> Volunteer. Provide the complete source code as a downloadable archive.
- [x] **Required stack and responsive interface** — Frontend: React with React Router and CSS. Backend: Node.js with Express. Database: MongoDB with Mongoose. API: REST with JWT authentication and passwords hashed by bcrypt. Use Leaflet/OpenStreetMap without a paid API key for picking and showing animal locations. Use Multer for animal photo uploads. Deliver a responsive, friendly UI with a paw/animal theme.
- [x] **Authentication, roles and user workflow** — Users can register and log in; frontend routes and backend middleware are role-protected. Roles are user, volunteer, shelter, and admin. Forms validate input and show clear errors. A user can report an injured/stray animal with photo upload, map location, animal type, description, and assistance required; track report status; browse animals available for adoption; and report a lost or found pet.
- [x] **Rescue reporting, priority and location** — Animal reports store animalType, description, photo, location (lat, lng, address), date, assistanceRequired, priority, status, verified (boolean), reporterId, and assignedVolunteerId. Priority values are Emergency (severely injured), Urgent (sick/injured), and Normal (food/shelter), with red/orange/green color-coded badges. Volunteer requests are sorted with the most urgent first.
- [x] **Volunteer/rescuer workflow** — Volunteers/rescuers can view nearby assistance requests sorted by priority, accept a rescue request, see the reporter's contact details, update status through Pending -> Accepted -> In Progress -> Resolved, and mark a case resolved. Volunteers store userId, name, contact, area, and availability.
- [x] **Shelter and adoption workflow** — Shelters can add shelter information, add animals for adoption, update adoption status between Available and Adopted, and manage incoming assistance requests. Adoption records include animalType, age, gender, description, photo, shelterId, and adoptionStatus. Shelter records include name, address, location, phone, email, and description.
- [x] **Administrator workflow** — Admins can manage users and volunteers; verify reports; remove fake/inappropriate reports; monitor all rescue cases; and manage shelter information.
- [x] **Lost/found and seed records** — Users can report a lost or found pet. LostFound records include type (lost/found), animalType, description, photo, location, contact, and status. A seed script supplies exactly these sample categories/counts: 1 admin, 2 volunteers, 2 shelters, 5 reports, and 5 adoptable animals.
- [x] **Pages and end-to-end rescue flow** — Provide Home, Report an Animal, Request Rescue, Find Assistance, Adopt an Animal, Shelters & Rescue Centers, Login/Register, User Dashboard, Volunteer Dashboard, Admin Dashboard, and Contact/Help pages. Verify the main flow: report -> volunteer accepts -> resolved.
- [ ] **Production container and publish** — Commit a root Dockerfile that installs from the pinned lockfile, builds the React client, serves it from Express, listens on the host-provided `PORT` (default 3000), and has an unauthenticated readiness endpoint returning 2xx when MongoDB is connected. Configure Webdev `deploy.healthPath`. Require a production-scoped MongoDB URI and PawCare-specific JWT secret through secure input; never copy development credentials to production. Retry Webdev Publish after the configuration and secret inputs are available, and report its confirmed result or blocker.
